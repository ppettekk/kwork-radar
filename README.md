# Kwork Radar

Монитор биржи проектов Kwork: ловит новые заказы с числом откликов до N,
фильтрует по бюджету и ключевым словам и присылает в Telegram карточку
проекта вместе с готовым черновиком отклика (CloseRouter).

Фильтр «до 5 откликов» отдаётся на сторону Kwork - параметр `kworks_filter_to`
внутреннего API, а не отсев постфактум. Локально он ещё раз проверяется на случай,
если выдача успела обновиться.

## Установка

```bash
git clone <repo> kwork-radar && cd kwork-radar
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполнить `.env`, затем узнать ID нужных рубрик:

```bash
python main.py categories
```

Вывод - дерево вида `=== 11  Разработка и IT` и вложенные подрубрики с ID.
Скопировать нужные в `CATEGORIES` через запятую. Пустое значение = «избранные
рубрики» аккаунта (настраиваются в профиле на сайте), `all` = все подряд.

Отредактировать `profile.md` - этот текст уходит в промпт и определяет, насколько
отклик звучит как твой. Чем конкретнее стек и чем чётче список «за что не берусь»,
тем чаще модель отвечает `SKIP` на мусорные заказы вместо натужного отклика.

## Запуск

```bash
python main.py
```

Первый запуск помечает текущую выдачу как просмотренную и ничего не шлёт
(`NOTIFY_ON_FIRST_RUN=false`), иначе прилетит полсотни сообщений разом.

## Что приходит в Telegram

1. Карточка: заголовок, бюджет, число откликов, статистика заказчика
   (сколько проектов размещал, какой процент найма), время до закрытия, описание.
   Кнопки: «Проект» и «Откликнуться» (сразу на форму отклика).
2. Вторым сообщением идёт черновик отклика в блоке `<code>`. Тап по блоку копирует
   текст целиком, Telegram показывает «Скопировано». Кнопка «♻️ Другой вариант»
   перегенерирует с большей температурой.

Черновик это заготовка, а не финал. Перед отправкой стоит хотя бы переписать
уточняющий вопрос под себя: заказчики уже научились узнавать шаблонные отклики.

### Что модель не пишет никогда

Сроки и деньги полностью убраны из промпта: ни дней, ни «оперативно», ни цены,
ни бюджета. Это остаётся на твоё усмотрение при отправке.

Тире тоже запрещены. Промпт требует перестраивать предложение, вывод дополнительно
прогоняется через `normalize()`, который заменяет все виды длинных тире на дефис
и срезает markdown. Если дефис в роли тире всё-таки остался, включается один
дешёвый проход переписывания (`REPAIR_DASHES=true`). Дефисы внутри слов
(«веб-разработка») не трогаются.

## Настройки

| Переменная | Смысл |
|---|---|
| `MAX_OFFERS` | Максимум откликов у проекта (уходит в `kworks_filter_to`) |
| `MIN_PRICE` / `MAX_PRICE` | Границы бюджета, ₽ |
| `HIRING_FROM` | Минимальный процент найма у заказчика - отсекает тех, кто вечно смотрит и не нанимает |
| `INCLUDE_KEYWORDS` | Если задано - проект должен содержать хотя бы одно слово |
| `EXCLUDE_KEYWORDS` | Стоп-слова, проверяются первыми |
| `POLL_INTERVAL` | Секунды между опросами. Ниже 30 не стоит |
| `LLM_ENABLED` | `false` даёт только уведомления, без обращений к CloseRouter |
| `REPAIR_DASHES` | Переписывать черновик, если в нём остались тире |

## Деплой на VPS

Скопировать каталог на сервер и прогнать `setup.sh` от root. Ubuntu 22.04/24.04,
Debian 11/12.

```bash
scp -r kwork-radar root@SERVER:/root/
ssh root@SERVER
cd /root/kwork-radar
bash setup.sh --dry-run     # посмотреть, что будет сделано
bash setup.sh
```

Скрипт ставит пакеты, создаёт swap на 1 ГБ (на 768 МБ RAM без него процесс
ловит OOM), заводит системного пользователя `radar`, разворачивает проект
в `/opt/kwork-radar`, собирает venv, пишет юнит systemd с ограничением памяти
и урезает лимит журналов до 200 МБ. Запускать можно повторно, ничего не ломает
и `.env` не перезатирает.

Флаги: `--dry-run`, `--no-swap`, `--swap 2G`, `--dir /srv/app`, `--user bot`,
`--tz Europe/Moscow`.

Про диск. Пакеты ставятся с `--no-install-recommends` и без системного `python3-pip`:
в Ubuntu 22.04 pip по рекомендациям тянет `build-essential`, `gcc` и `python3-dev`,
это около полутора гигабайт, а на VPS с диском 5 ГБ такое не прощается. Внутри venv
pip всё равно появляется через ensurepip. Размер swap подбирается по реально
свободному месту с резервом 1.2 ГБ: если места мало, swap уменьшается или
пропускается, но установка не падает.

Сервис стартует автоматически, только если `.env` уже заполнен. Иначе он
включается в автозапуск и ждёт, а скрипт печатает список дальнейших шагов.

```bash
systemctl status kwork-radar
journalctl -u kwork-radar -f
systemctl restart kwork-radar
```

### Первым делом проверить IP

```bash
cd /opt/kwork-radar && sudo -u radar .venv/bin/python main.py categories
```

Появился список рубрик, значит Kwork пускает с этого адреса. Ошибка про робота
означает, что IP датацентра в блоклисте: нужен российский резидентный socks5
в `KWORK_PROXY` или сервер в другой локации.

## Подводные камни

**«Подтвердите, что вы не робот».** Kwork режет по IP, не по аккаунту. Лечится
прокси в `KWORK_PROXY` (`pip install "kwork[proxy]"` для socks5) и адекватным
интервалом опроса. При входе с нового IP может понадобиться `KWORK_PHONE_LAST`.

**Библиотека неофициальная.** Часть методов ходит в web-эндпоинты kwork.ru и может
сломаться после любого релиза площадки. Если `get_projects` начал падать -
смотреть issues репозитория `kesha1225/kwork`.

**Автосбор данных формально против пользовательского соглашения Kwork.** Для личного
монитора риск невелик, но раздавать фид наружу не стоит.

**Расход связок.** Радар только уведомляет, отклики остаются ручными - и это
осознанно. Автоматический отклик на всё подряд сжигает связки быстрее, чем приносит
заказы; ценность тут в скорости реакции на подходящее, а не в объёме.
